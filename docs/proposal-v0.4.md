**Status:** Research candidates only; not approved for implementation or operational instructions.
**Branch basis:** 0.3 discussion branch after merging released 0.2.5 (merge 1847f947c6ce36d74a091a231bf6eaafa963e629). Resynchronize with main after 0.3 is released; re-evaluate against the actual released contracts and remove stale copies of the 0.3 proposal. No release bump on this branch yet.

## Scope separation
0.3 implements P01–P06 and P07.1 (deterministic Ledger append, including its ordinary code tests). Retain observations.md as generalized evidence, not normative guidance. The remaining P07 ideas, P08 and P09 are deferred here for investigation, not automatic implementation. Preserve the existing lifecycle, independent reviews, human authority and portable fallback. No new gate, workflow engine or global runtime dependency is presumed.

## P07 — Deterministic Responsibility (continued)
Move genuinely deterministic responsibilities out of model reasoning where a small reliable mechanism can own them. Ledger append is P07.1 in 0.3; do not duplicate it. Investigate validation of other artifact schemas/identities, cross-record consistency, legal state transitions, recovery mechanics, and host-native waiting/event delivery. Consider optional harness hooks for observation, validation or enforcement; compare actual installed client versions, event coverage (including nested invocations), interruption semantics and failure modes. Separate correctness of a transition from authorization to make it; never allow code or hooks to silently widen scope or declare acceptance. Prefer incremental helpers over a mandatory orchestrator. Compare total cost, complexity, portability and failure recovery before adopting anything.

Sources to revalidate: [Codex hooks](https://developers.openai.com/codex/hooks), [Claude Code hooks](https://code.claude.com/docs/en/hooks), [Codex idle wake PR](https://github.com/openai/codex/pull/54961), [Codex wait implementation](https://github.com/openai/codex/blob/main/codex-rs/core/src/tools/handlers/multi_agents_v2/wait.rs). These are leads, not proof of installed-client support.

## P08 — Behavioral Regression Tests
Audit of textual contracts is not a behavioral test. Develop bounded synthetic tasks and compare actual model behavior and outcome, with no private consumer artifacts. Candidate scenarios: delayed reviewer with direct effective waiting; no behavioral substitution (not just absence of true); verified automatic continuation including completion/turn-end race, nonterminal messages, failure, interruption and deadlines; current/observed/historical timestamp capture; compaction and governing definition recovery; seeded material reviewer findings; complete objectives but insufficient outcome; material risk trigger and authorized replanning. Use actual installed Codex and Claude Code versions, selected model/effort, pinned skill revision, reproducible workload and explicit expected result. Distinguish runtime limitations from instruction noncompliance. Compare batch sizes, reviewer models and cross-model independence, marginal review value, goal drift and recovery cost, human attention/intervention, review volume and total cost per accepted outcome. Measure actual parent inference/tool calls, elapsed wait, tokens cached/uncached and result-consumption delay where available; do not infer billing or causal attribution from associated tokens. Keep experiments outside ordinary Task obligations; no mandatory telemetry or new gate.

See observations.md OBS-001–004 for observed failures, measurement caveats and specific wait experiments; OBS-005 for positive evidence. [OpenAI skill eval guidance](https://developers.openai.com/blog/eval-skills). Validate 0.3 behavior before deciding additional fixes; an ineffective experiment is not a reason to spin or bypass a gate.

## P09 — Native Goal Integration
Investigate Codex native /goal or analogous supported runtime mechanisms only as an optional continuation aid for the already human-approved governing Task Definition. Verify actual installed capabilities, terminal and failure behavior, deadlines, pause/stop, recovery and scope limits. Do not create a second source of truth: the approved Brief/Plan and accepted amendments remain authoritative; any native goal must be derived, identifiable and updated only through authorized changes. No native success signal may replace independent acceptance or human launch. Compare to current waiting/recovery fallback; avoid coupling portable skill instructions to one host. Research before implementing; [Codex documentation](https://developers.openai.com/codex) is a starting point, not verified evidence of local feature support.

## Decision criteria
Adopt only demonstrated improvements in independently verified outcomes, reliability or total cost including human attention; preserve existing approval boundaries, durable evidence, rolling-wave planning and independent review. Explicitly decide scope and run the complete affected-skill audit before any release.
