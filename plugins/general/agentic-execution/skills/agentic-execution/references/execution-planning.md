# Execution Planning — rolling wave

Only enter after verifying independent definition acceptance, distinct initial human Brief/Plan approvals, explicit launch and current effective definition (including approved/accepted amendments). Read [Human approvals](human-approvals.md) if any gate remains pending and [Recovery](state-and-recovery.md) if interrupted. No default human approval of the derived Execution Plan. Create the Execution Plan only after initial launch; continue the already initialized root Task Ledger.

## Plan structure

Keep one mutable execution-plan.md for intended work. Link governing Brief/Plan, effective definition and major source/decision versions. Cover **every** Objective and obligation end-to-end. Carry applicable Task- and Objective-level Tools & Skills into affected work, prerequisites and evidence targets. Reference any external workflow/decomposition artifacts where useful rather than duplicating them; retain Single Focus Steps, dependencies and independent gates in this lifecycle. Use:
- **Current Batch:** stable BNN ID, focus/deliverable, Objective mapping, actual prerequisites, dependencies, fully specified Single Focus Steps, expected checks/evidence.
- **Next Batch:** provisional scope, likely decomposition, prerequisites, assumptions/risks.
- **Remaining overview:** high-level purpose, Objective coverage and important dependencies.
- Historical/suspended/superseded batch IDs and references to Task Ledger where relevant; never rewrite accepted history.

Use only applicable horizons. If no executable work remains (including after a definition re-entry or profile-only amendment at a final review gate), record that fact, verify that all mandatory work and relevant accepted checkpoints/evidence still satisfy the effective definition, and route to [Final acceptance](final-acceptance.md). Do not invent a Current/Next Batch or E-Step just to fill the template; if any work or revalidation is needed, plan and accept the actual batch before executing it.

An executable E-Step has stable E01, E02, etc., one coherent focus, required input/dependencies, bounded action and intended output, verifiable completion condition and evidence target; map to relevant O-IDs. Related checks may share one E-Step if they support one coherent deliverable, independently identifiable evidence and verifiable completion conditions; split unrelated outcomes, dependencies or risks when necessary. Allocate monotonically and never reuse IDs; provisional future outlines need not have concrete E-IDs. No fictional E00. Batch IDs stable and never reused, including correction batches. Group related work by meaningful deliverable/check cost, not fixed size. Dependencies are actual required results, not numerical order or every prior batch by default. Distinguish within-batch inputs that earlier Steps will produce from external or earlier-batch inputs that must already be available. No cycles. Reorder pending work if needed.

## Planning Acceptance

For each new batch identity start a fresh Combined Execution Batch Reviewer; for changes or restoration of the same suspended batch retain its reliable compatible reviewer, or replace it under Reviewers' recovery rule. Provide effective Brief/Plan, original material sources/decisions, identifiable Execution Plan, detailed Current plus full-task overview, prerequisite evidence and target checks. Require review of:
1. Single Focus and actionable bounded Steps.
2. Preservation of all governing objectives, methodology, constraints (including applicable accepted strategic Tools & Skills choices, required workflows and their scope) and evidence, including overview coverage/dependencies.
3. Coherent prerequisites and scheduling; currently required inputs available, within-batch prerequisites ordered and verified before dependent work.
4. Meaningful proportionate verifiable checks/evidence targets; expensive runs include actual execution identity, clean/fresh vs reused evidence, privacy/permission safeguards and recovery as applicable (see [Execution](execution.md)).
5. No invented human decisions or disguised strategic change.

Correct and resubmit until explicit **Planning Acceptance for this Current Batch only** (definition, plan version and material prerequisite evidence). Persist/read back and verify. No execution of its Steps before this gate. Next/Remaining are never pre-accepted. Changes to the effective definition or material changes to current executable scope or prerequisites require renewed Planning Acceptance before affected work, not retroactive permission. Routine implementation within accepted scope needs no extra gate.

After accepted execution and verified checkpoint, first reconcile any suspended dependent batches under [Changes and corrections](changes-and-corrections.md); otherwise promote/elaborate Next, refresh overview and start a fresh reviewer. If strategy fails, or earlier prerequisites need correction, follow [Changes and corrections](changes-and-corrections.md). Keep only one executable Current Batch.
