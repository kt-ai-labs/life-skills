# Independent review contract — Mode C

[Reviewers](reviewers.md) owns profile, context and invocation policy; phase reference owns gate scope; [Evidence and checkpoints](evidence-and-checkpoints.md) owns recoverable versions. Reviewer reads, Executor writes.

## Assignment and response

Identify Task, role/gate, batch/definition cycle, governing Skill operational version and recoverable submitted versions. Assign the authorized read-only Reviewer role, not Executor. Provide applicable contract and gate instructions from that exact Skill version by recoverable access or relevant excerpts. In retained contexts reuse current guidance; refresh only changed, missing or uncertain instructions. A different harness or installed version must not silently change the contract. Preserve the actual submitted versions before invocation; freeze affected writes or use pinned access. Provide direct, authorized read access to relevant original request/material dialogue, governing sources/decisions, effective Brief/Plan, work/evidence and prior findings where relevant. Verify the receiving context/harness is permitted to access private material; do not expand disclosure or permissions for review. Do not supply private reasoning or entire conversation as proof. Fresh final substantive review starts from obligations and primary outputs, not Executor status.

Require actual response with reviewed versions/scope and inaccessible material, stable finding IDs, severity, precise location, evidence, consequence and concrete correction; flag reserved human decisions/options. Require explicit **Accepted (gate + version)**, **Changes required**, or **Blocked (reason)**; identify unmet conditions. Conditional acceptance with unmet required conditions remains pending. Correction rounds dispose prior findings and give required whole-scope decision. Definition re-entry also gives renewed approval required/waived/uncertain per affected artifact/version with reason.

Critical: core result invalid or serious integrity/permission breach. High: major obligation/correctness/verification gap. Medium: substantive localized validity/evidence/process issue. Low: nonblocking improvement. C/H/M, missing mandatory checks/evidence, unresolved reserved decisions required at this gate or missing required review provenance block acceptance irrespective of labels. During definition, a fully specified justified proposal explicitly awaiting human approval may pass readiness/definition review, but is not a confirmed decision or execution authorization. Silence/no findings is not acceptance.

**Historical process deviations:** A demonstrated process violation is assessed under the governing revision, with its original severity and actual consequences preserved. An irreversible historical deviation (e.g. wasted waiting activity or a missed contemporaneous capture) cannot be undone. Resolve any ongoing violation and all remediable effects on obligations, authority, correctness, evidence, tracking and recovery; record the actual violation, residual limitations and supported corrective disposition in existing records without rewriting history or inventing evidence. The applicable independent Reviewer may explicitly close the finding as resolved with an irreversible historical residual only when all required checks, evidence, authority and provenance are satisfied, the deviation is no longer ongoing, and no blocking consequence remains; explain the basis in the actual decision. Do not downgrade to avoid correction, waive mandatory requirements, excuse serious integrity/permission breaches, or repeat otherwise valid work solely to pretend a historical deviation did not occur. Unresolved C/H/M findings still block acceptance. No extra review gate or mandatory forensic replay.

## One durable record per round

Use existing Task review directory and stable definition cycle/batch + gate + sequential round. For initial Discovery use `D00-initial-r01.md`, `D00-initial-r02.md`, etc.; for later Assignment milestone reviews use `D01-results-r01.md`, etc. D00 identifies the initial review gate, not a limit on its scope (review the drafts, applicable orientation and queue) or evidence of a newly executed D00 on re-entry. For re-entry use a distinct cycle prefix, e.g. `C02-D00-initial-r01.md` or `C02-D05-results-r01.md`; allocate cycles monotonically, retain existing assignment IDs and use distinct gate names for non-assignment milestones such as `readiness-r01.md` or `C02-readiness-r01.md` (a combined initial/readiness decision remains in its initial round). For other definition gates use a cycle-specific identity; execution batch example `B01-planning-r01.md`. Allocate rounds monotonically within each logical gate identity, including superseded rounds and existing historical rounds using older names. On adoption recover the actual cycle/gate/round identities from the existing records, continue their numbering and preserve historical filenames and links; if identities are uncertain reconcile them before allocating the next round. Never overwrite another cycle, gate or round. Before invoking, persist/read back a pending round with scope, governing Skill identity, recoverable submitted versions and confirmed requested profile. Link preparation, actual invocation/start, response/outcome and material dispositions to the [Task Ledger](task-ledger.md) using the round identity. Prepared is not invoked: once checks pass, invoke. Record the attempt and available handle/receipt promptly; distinguish preparation, invocation and completion in existing fields. If the submitted scope or prerequisites become invalid before invocation, close the prepared round as superseded and not invoked; prepare the current round only when ready. If already invoked or invocation is uncertain, reconcile actual host state and restrictions before replacement; preserve any actual response but never apply it to changed governing content without the required independent verification. Missing handle is not proof of absence. Follow the Skill's waiting rules. Close the same record with the actual response, a verified never-invoked supersession, or the verified interruption/termination and supersession disposition of an invoked round without a completed response. Replace obsolete pending labels in the envelope and link any replacement round. Record the actual disposition promptly in the Task Ledger; no additional review gate. Do not rewrite a completed round or invent a lost response; append or link subsequent provenance corrections, invalidation and disposition without altering the actual response. A compact envelope is enough:
- Gate/role/scope, preparation/invocation/completion UTC times captured per the [Task Ledger timestamp policy](task-ledger.md#timestamp-capture), distinguishing observed from actual remote times where applicable; reuse corresponding event timestamps, harness, invocation/context handle or available receipt and isolation/completion basis, replacement lineage. If durable host ID unavailable, say so; preserve actual response and available invocation evidence sufficient to establish independence/completion.
- Requested model and effort; each effective value with host-established / human-attested / unknown and basis; selection method and available mismatch/fallback checks per Reviewers.
- Governing Skill revision (a pointer to the specific recorded revision suffices) and recoverable submitted versions of governing inputs, plan, work/evidence as applicable. Base commit alone is insufficient for uncommitted content. Do not retroactively assign a Skill version to historical reviews.
- Actual independent response verbatim or authorized durable retrievable link, including explicit decision. Executor summary is not actual response.
- Dispositions, corrected evidence and subsequent decisions via links. Preserve original round; do not recreate missing old responses from memory.

Before crossing gate, read back record/response (including retrievable pointer) and verify actual submitted scope, governing review contract and current governing state. A pending round under a changed contract requires reconciliation and affected independent verification per [Start and resume](start-and-resume.md#skill-identity-and-continuity); do not silently reinterpret its decision. If mandatory primary material was inaccessible, gate remains pending even on Accepted; restore authorized access and obtain independent verification. Optional inaccessible sources need not block independently supported obligations. Fix findings, verify corrections, resubmit identifiable version, obtain explicit closure and acceptance using retained context when allowed. Lost response or insufficient recoverable scope → repeat pending review legitimately or stop; never backfill fictional acceptance. Unknown effective profile alone is handled solely by Reviewers' policy.
