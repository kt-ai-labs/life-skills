# Independent review contract — Mode C

[Reviewers](reviewers.md) owns profile, context and invocation policy; phase reference owns gate scope; [Evidence and checkpoints](evidence-and-checkpoints.md) owns recoverable versions. Reviewer reads, Executor writes.

## Assignment and response

Identify Task, role/gate, batch/definition cycle, governing Skill operational version and recoverable submitted versions. Assign the authorized read-only Reviewer role, not Executor. Provide applicable contract and gate instructions from that exact Skill version by recoverable access or relevant excerpts. In retained contexts reuse current guidance; refresh only changed, missing or uncertain instructions. A different harness or installed version must not silently change the contract. Preserve the actual submitted versions before invocation; freeze affected writes or use pinned access. Provide direct, authorized read access to relevant original request/material dialogue, governing sources/decisions, effective Brief/Plan, work/evidence and prior findings where relevant. Verify the receiving context/harness is permitted to access private material; do not expand disclosure or permissions for review. Do not supply private reasoning or entire conversation as proof. Fresh final substantive review starts from obligations and primary outputs, not Executor status.

Require actual response with reviewed versions/scope and inaccessible material, stable finding IDs, severity, precise location, evidence, consequence and concrete correction; flag reserved human decisions/options. Require explicit **Accepted (gate + version)**, **Changes required**, or **Blocked (reason)**; identify unmet conditions. Conditional acceptance with unmet required conditions remains pending. Correction rounds dispose prior findings and give required whole-scope decision. Definition re-entry also gives renewed approval required/waived/uncertain per affected artifact/version with reason.

Critical: core result invalid or serious integrity/permission breach. High: major obligation/correctness/verification gap. Medium: substantive localized validity/evidence/process issue. Low: nonblocking improvement. C/H/M, missing mandatory checks/evidence, unresolved reserved decisions required at this gate or missing required review provenance block acceptance irrespective of labels. During definition, a fully specified justified proposal explicitly awaiting human approval may pass readiness/definition review, but is not a confirmed decision or execution authorization. Silence/no findings is not acceptance.

## One durable record per round

Use existing Task review directory and stable cycle/batch + gate + sequential round (e.g. B01-planning-r01.md). Before invoking, persist/read back a pending round with scope, governing Skill identity, recoverable submitted versions and confirmed requested profile. Prepared is not invoked: once checks pass, invoke. Record the attempt and available handle/receipt promptly; distinguish preparation, invocation and completion in existing fields. If the submitted scope or prerequisites become invalid before invocation, close the prepared round as superseded and not invoked; prepare the current round only when ready. If already invoked or invocation is uncertain, reconcile actual host state and restrictions before replacement; preserve any actual response but never apply it to changed governing content without the required independent verification. Missing handle is not proof of absence. Follow the Skill's waiting rules. Close the same record with the actual response, a verified never-invoked supersession, or the verified interruption/termination and supersession disposition of an invoked round without a completed response. Replace obsolete pending labels in the envelope and link any replacement round. Do not rewrite a completed round or invent a lost response; append or link subsequent provenance corrections, invalidation and disposition without altering the actual response. A compact envelope is enough:
- Gate/role/scope, available preparation/invocation/completion UTC times (unknown where unavailable), harness, invocation/context handle or available receipt and isolation/completion basis, replacement lineage. If durable host ID unavailable, say so; preserve actual response and available invocation evidence sufficient to establish independence/completion.
- Requested model and effort; each effective value with host-established / human-attested / unknown and basis; selection method and available mismatch/fallback checks per Reviewers.
- Governing Skill revision (a pointer to the specific recorded revision suffices) and recoverable submitted versions of governing inputs, plan, work/evidence as applicable. Base commit alone is insufficient for uncommitted content. Do not retroactively assign a Skill version to historical reviews.
- Actual independent response verbatim or authorized durable retrievable link, including explicit decision. Executor summary is not actual response.
- Dispositions, corrected evidence and subsequent decisions via links. Preserve original round; do not recreate missing old responses from memory.

Before crossing gate, read back record/response (including retrievable pointer) and verify actual submitted scope, governing review contract and current governing state. A pending round under a changed contract requires reconciliation and affected independent verification per [Start and resume](start-and-resume.md#skill-identity-and-continuity); do not silently reinterpret its decision. If mandatory primary material was inaccessible, gate remains pending even on Accepted; restore authorized access and obtain independent verification. Optional inaccessible sources need not block independently supported obligations. Fix findings, verify corrections, resubmit identifiable version, obtain explicit closure and acceptance using retained context when allowed. Lost response or insufficient recoverable scope → repeat pending review legitimately or stop; never backfill fictional acceptance. Unknown effective profile alone is handled solely by Reviewers' policy.
