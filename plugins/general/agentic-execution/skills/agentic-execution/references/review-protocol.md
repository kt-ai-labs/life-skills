# Independent review contract — Mode C

[Reviewers](reviewers.md) owns profile, context and invocation policy; phase reference owns gate scope; [Evidence and checkpoints](evidence-and-checkpoints.md) owns recoverable versions. Reviewer reads, Executor writes.

## Assignment and response

Identify Task, role/gate, batch/definition cycle, governing Skill operational version and recoverable submitted versions. Provide the authorized read-only reviewer the relevant review contract and phase/gate instructions from that exact Skill version (or equivalent recoverable access to them); explicitly assign the Reviewer role, not the Executor lifecycle. A different harness or installed version must not silently change the contract. Preserve the actual submitted versions before invocation; freeze affected writes or use pinned access. Provide direct, authorized read access to relevant original request/material dialogue, governing sources/decisions, effective Brief/Plan, work/evidence and prior findings where relevant. Verify the receiving context/harness is permitted to access private material; do not expand disclosure or permissions for review. Do not supply private reasoning or entire conversation as proof. Fresh final substantive review starts from obligations and primary outputs, not Executor status.

Require actual response with the governing review contract identity, reviewed versions/scope and inaccessible material, stable finding IDs, severity, precise location, evidence, consequence and concrete correction; flag reserved human decisions/options. Require explicit **Accepted (gate + version)**, **Changes required**, or **Blocked (reason)**; identify unmet conditions. Conditional acceptance with unmet required conditions remains pending. Correction rounds dispose prior findings and give required whole-scope decision. Definition re-entry also gives renewed approval required/waived/uncertain per affected artifact/version with reason.

Critical: core result invalid or serious integrity/permission breach. High: major obligation/correctness/verification gap. Medium: substantive localized validity/evidence/process issue. Low: nonblocking improvement. C/H/M, missing mandatory checks/evidence, unresolved reserved decisions required at this gate or missing required review provenance block acceptance irrespective of labels. During definition, a fully specified justified proposal explicitly awaiting human approval may pass readiness/definition review, but is not a confirmed decision or execution authorization. Silence/no findings is not acceptance.

## One durable record per round

Use existing Task review directory and stable cycle/batch + gate + sequential round (e.g. B01-planning-r01.md). Before invoking, persist/read back a pending round with scope, governing Skill identity, recoverable submitted versions and confirmed requested profile; add the invocation handle/receipt as soon as available. If interrupted before the receipt is saved, reconcile actual host state before retrying; an absent handle is not proof no invocation exists. Complete the same record with the actual response or verified interruption/termination and supersession disposition if no completed response exists; link any replacement round. Do not rewrite a completed round or invent a lost response; append or link subsequent provenance corrections, invalidation and disposition without altering the actual response. A compact envelope is enough:
- Gate/role/scope, UTC or explicitly unknown, harness, invocation/context handle or available receipt and isolation/completion basis, replacement lineage. If durable host ID unavailable, say so; preserve actual response and available invocation evidence sufficient to establish independence/completion.
- Requested model and effort; each effective value with host-established / human-attested / unknown and basis; selection method and available mismatch/fallback checks per Reviewers.
- Recoverable governing Skill identity and submitted versions of governing inputs, plan, work/evidence as applicable; reference the existing Task identity record when sufficient. Base commit alone is insufficient for uncommitted content. Preserve historical review records without retroactively assigning a Skill version.
- Actual independent response verbatim or authorized durable retrievable link, including explicit decision. Executor summary is not actual response.
- Dispositions, corrected evidence and subsequent decisions via links. Preserve original round; do not recreate missing old responses from memory.

Before crossing gate, read back record/response (including retrievable pointer) and verify actual submitted scope, governing review contract and current governing state. A pending round under a changed contract requires reconciliation and affected independent verification per [Start and resume](start-and-resume.md#skill-identity-and-continuity); do not silently reinterpret its decision. If mandatory primary material was inaccessible, gate remains pending even on Accepted; restore authorized access and obtain independent verification. Optional inaccessible sources need not block independently supported obligations. Fix findings, verify corrections, resubmit identifiable version, obtain explicit closure and acceptance using retained context when allowed. Lost response or insufficient recoverable scope → repeat pending review legitimately or stop; never backfill fictional acceptance. Unknown effective profile alone is handled solely by Reviewers' policy.
