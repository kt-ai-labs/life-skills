# Task Definition — initial and re-entry

Definition is interactive planning, not substantive Objective execution. Use [Task artifacts](task-artifacts.md) for formats.

## Initial sequence

1. Verify initialized [Task Ledger](task-ledger.md); preserve original request, provided sources, material dialogue and decisions. Retain useful existing human-authored Brief/Plan content and trace changes; resolve framing only as needed for an honest draft.
2. Complete brief D00 orientation, save its report and local index, verify and merge the entry into the parent Context index; draft Brief, Plan and living Discovery Plan together. Defer deeper questions to [Discovery](discovery.md).
3. Resolve all three reviewer roles for both Codex and Claude Code by default per [Reviewers](reviewers.md), unless the human explicitly narrows the harness scope or a documented confirmed legacy scope applies. Record explicit selections already given; propose defaults for missing mappings and ask only for missing or ambiguous required confirmations. No main Discovery before confirmation.
4. Follow Discovery's initial independent Batch review, assignments/milestones and explicit readiness. Correct blocking issues before advancing.
5. After readiness, invoke the fresh Final Task Definition Reviewer, distinct from Discovery reviewer, as soon as the pending round and prerequisites are verified. Apply [Review protocol](review-protocol.md): submit original request/dialogue, source/decision versions, Brief/Plan, Discovery Plan, Context index, relevant Task Ledger history and primary evidence. Check scope fidelity, both artifact contracts in Task artifacts (including separate, ordered Brief framing, Intended Outcome and Objectives with distinct meanings, one-to-one Objective mapping, and confirmed default dual-harness Reviewer Profiles or a documented human restriction or grandfathered legacy scope per Reviewers), strategy (including applicable Task- and Objective-level Tools & Skills choices, scope, feasibility and preservation of human-required workflows), source authority, evidence/verification per Objective, Discovery accounting (including material lifecycle tracking against the authoritative records) and blockers. Distinguish fully specified proposed choices from confirmed human decisions; review acceptance cannot authorize a reserved choice. Explicitly assess outcome sufficiency: whether the framing and Intended Outcome address the original human intent, and whether the combined Objectives, strategy, dependencies and evidence/verification obligations are sufficient to address that outcome. Completing every listed Objective is not sufficient if their combined result would leave a material part of the Intended Outcome unaddressed. Correct material gaps through existing Definition/Discovery and approval rules; do not assume a positive research result. This role covers substance and completeness of definition.
6. Correct through needed Discovery/drafting, recheck affected readiness and resubmit to retained final reviewer; broad redesign or invalid context requires fresh review. Obtain explicit current-version acceptance.
7. Present accepted Brief and Plan together; follow [Human approvals](human-approvals.md) for separate decisions and explicit launch (may be given together). If human changes reviewed content, reconcile both artifacts and re-review affected definition/readiness; preserve only compatible approvals. Do not create Execution Plan until launch.

## Re-entry

In an already launched Task, use [Changes and corrections](changes-and-corrections.md): preserve prior effective definition, suspend affected work, do only needed Discovery, re-establish independent readiness and use a fresh Final Task Definition Reviewer with explicit approval-impact assessment. Apply renewed approvals where required, establish effective version, return to Execution Planning. No automatic second launch; never self-waive approval impact.
