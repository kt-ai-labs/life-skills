# Human assistance and downloads

Use when a material research check needs human interaction or a manually saved file. Follow the browser-session boundary in SKILL.md; no particular browser tool is required.

## Agent-first assistance and Full Research Pause

1. **Diagnose:** inspect current state and try reasonable permitted alternatives. Identify what actually failed and the evidence still needed. Do not ask for help on every transient error or use a human to bypass an explicit access/security restriction.
2. **Prepare and request assistance:** if a person could safely close the gap, prepare the relevant page and any needed checkpoint before asking. Identify the exact website/URL and specific provider, product/tariff, document or UI element, what was attempted, the precise action or information needed and what constitutes sufficient completion. When several items are visible, name the requested one and a distinguishing label; do not ask only to "open the correct tariff." State actions outside the authorized scope. Accept any suitable form of assistance, including screenshots, copied text, documents, URLs, a navigated page or a document location; do not require a transfer procedure or saving to Downloads. Present both routes together when available:
   - **Shared Browser:** leave the relevant page in the existing authorized session and explain its actual control mechanism. Confirm sharing/retention support; visibility alone does not prove user control. Do not promise isolation or shared control without evidence. For Playwright Dashboard use the CLI reference below, not an invented handoff command.
   - **Independent Browser:** provide the URL, exact target item, unresolved question, relevant search inputs and approximate navigation to the information. Label unverified steps and allow for a different interface in the user's browser. This route remains available even when shared control works.
3. **Pause the entire research workflow:** immediately after requesting assistance, stop all automated browser interactions and all other research work. Do not navigate, create, switch, reload or close tabs in any session, continue independent research, or start parallel research tasks. Preserve the current state and wait for explicit user communication confirming completion or returning control, including for independent-browser assistance. Do not perform routine cleanup while waiting; explain any known session-lifetime limitation before yielding. A tool-call retry approval, a newly appearing file or an observed UI change is not confirmation from the user.
4. **Resume and verify:** only after explicit confirmation, inspect the current page or supplied evidence and verify identity, completeness and applicability to the original question before proceeding. For shared control, obtain fresh state from the same session/tab and reuse completed navigation. A click, screenshot or downloaded file alone does not prove the question is answered. If something is missing, explain the specific gap and request focused follow-up under the same pause rule. If the session expired, explain the loss and restore only what is needed after control returns. Continue the original substantive research, not merely document receipt.

If shared control is unavailable, say so and use the independent-browser route; do not attach to a personal profile through an unsupported integration. Assistance does not authorize changing the selected source or bypassing restrictions. If help fails or is declined, keep the gap unresolved and explain a concrete next step without repeating the same request; do not treat the offer as verified. Domain-specific legal and authorization boundaries still apply.

For Playwright CLI capabilities, use [the CLI reference](playwright-cli.md) only when that tool is available and permitted. Distinguish official documentation, installed-version support and behavior actually tested in this environment.

## Receiving a manually saved document

Ask where the file was saved if the location is not clear. Check actual filesystem/sandbox access; browser access does not imply access to the user's Downloads. On denial ask for an explicit file transfer or an accessible path, without broadening access silently.

For a known download folder, such as `~/Downloads`, prefer a bounded listing of names and metadata before requesting help and another after explicit return, when feasible; do not poll while paused. Examine recently added/modified suitable files and only a small set of likely candidates using filename, type, size and timestamps. Do not scan the home directory or unrelated document contents. The newest file is only a candidate: verify content, publisher/provider, document version and applicability to the target offer. If ambiguous, ask which file rather than guessing.

Browser-managed downloads may be in temporary storage, not system Downloads. Use the tool's reported path/location and check the file is accessible before closing the session. If needed, copy it to the task's authorized durable storage and verify the copy. Never delete or move the user's original download without separate permission. Preserve source/retrieval context and distinguish receiving a file from validating its contents; retention/naming belong to the task's workspace rules.
